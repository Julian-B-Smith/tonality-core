# LIBRARY — durable, evidence-backed lessons

Long-term memory for this project's knowledge loop. **Repo-shared
agent-process lessons only** — the hard-won, evidenced "how to work in this
repo without re-tripping a wire." Not decisions (→ DECISIONS.md), not task
state (→ ROADMAP.md), not machine-local facts (→ the human's global memory).

Entries are retrieved via [INDEX.md](INDEX.md). Format is `library-entry.3`
(canonical contract: `autonomous/kit/contracts/library-entry.md`). New lessons
enter as `tier: candidate` and become `canonical` on a second independent
occurrence or human review. Every entry states its own **falsifier** — the
observation that would retire it.

**Entry template**

```
[Lxxxx] <title> | tier: … | added: YYYY-MM-DD | tags: … | lesson: … | evidence: … | falsifier: … | supersedes: —
```

Never compare a before-number from one session against an after-number from another. Build both variants, run them ALTERNATING in one session, and re-measure at least one function you did NOT touch as a control — if the control moved, the whole pass is suspect. Min-over-repeats strips OS preemption but does not rescue this. | evidence: 2026-08-10 — a full pass over the ported surface came in ~2x slower than a later pass of the same binary; untouched functions (interval_vector, prime_form, reflection_residual) moved by the same factor as the edited one. [L0002] Prove an RT claim with two instruments — the allocation trap and the symbol audit see different things | tier: candidate | added: 2026-08-18 | tags: rt-safety, oracle-discipline | lesson: A runtime allocation trap only sees the code paths a sweep happens to execute; a per-function `nm -u` audit sees every path, including first-call static construction and exception machinery. Run both. The symbol audit is what actually substantiates "lock-free" — an `operator new` or `__cxa_guard_acquire` in the undefined-symbol list is disqualifying no matter what the trap observed. And isolate the translation unit: `nm -u` reports the WHOLE object, so constructing a warm-up handle in the same test file makes its constructor's guard look like part of the real-time path. | evidence: 2026-08-09/10 — the trap showed chirality_sign allocating 7 times / 1016 B only on its FIRST call in a fresh process; a warm sweep alone would have read clean. Separately, ZTableHandle::partner first audited as carrying __cxa_guard_acquire, which was the test TU's own static, not the call path; passing the handle in gave the true result (stack canary only). | falsifier: an allocation or lock introduced into this surface that a warm-sweep trap alone reliably catches without the symbol audit. | supersedes: —

[L0003] The mailbox is in the OTHER repo — looking locally reads as "no open exchanges" | tier: candidate | added: 2026-08-18 | tags: port-discipline, integrations | lesson: tonality-core is a CONSUMER, so it has no `integrations/` of its own: briefs, notices, responses and ratifications addressed to it all live in the provider's tree at `~/Documents/Tonality/integrations/tonality-core/`. Nothing in this repo changes when one arrives. A session that checks locally for open exchanges will find nothing and conclude, wrongly, that there are none — reading the provider's slot must be a deliberate step at session start. | evidence: 2026-08-09 — a session asked to act on `integrations/tonality-core/notice-foundations-rt-questions.md` found no such path in this repo; the file was in the Tonality tree, carrying a relayed FOUNDATIONS brief with the ball on us. | falsifier: this repo gaining its own `integrations/` directory as the primary inbound channel, or a mechanism that signals locally when a provider-side file lands. | supersedes: —

[L0004] Verify the count, not your arithmetic, before it propagates into three documents | tier: candidate | added: 2026-08-18 | tags: port-discipline, oracle-discipline | lesson: A small derived quantity stated in prose (a list length, a row count, an iteration bound) is worth actually printing before it is written down. It is cheap to compute and expensive to correct, because prose numbers propagate: the same figure lands in a code comment, a README, an exchange response and a commit message within minutes, and nothing gates prose. | evidence: 2026-08-18 — the chirality slice family was described as "66-element", then "30-element", in a header comment, the README, an exchange response and a report. Printing `kChiralitySliceCount` gave 36. All four sites had to be corrected; only the compiler knew. | falsifier: a derived count asserted from reasoning alone that survives review and never needs correction, in a repo where such counts are checkable in one command. | supersedes: —

[L0005] Never pipe a gate's output through `echo` when testing it — zsh eats the backslashes you are testing for | tier: candidate | added: 2026-08-18 | tags: oracle-discipline, ci-platform | lesson: When proving a detector fires, capture its output and re-emit it with `printf '%s\n'`, never `echo "$out"`. zsh's builtin `echo` interprets escape sequences by default, and `\U` is a unicode escape that swallows what follows it — so the very Windows-identity string the gate just caught is destroyed on its way to your assertion, and a PASSING gate reports as failing. The plant itself must also be written with `printf` for the same reason. General form: the test harness around a gate is code too, and a harness bug looks exactly like a gate bug. | evidence: 2026-08-18 kit retrofit — the leak_gate correctly fired on a planted drive-letter Windows identity path (not written literally here — this file is scanned by the very gate it describes) and named the file, but the check reported "DID NOT FIRE" because `echo "$out"` mangled `\Users` via zsh's `\U` handling and produced no matching line. Re-running the identical assertion with `printf '%s\n'` gave FIRED. The gate was never wrong. | falsifier: a shell in this ecosystem's default toolchain whose `echo` passes backslash sequences through unaltered, making the distinction moot. | supersedes: —
